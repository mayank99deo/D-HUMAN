- **Date:** 2026-11-19
- **Author:** `staff-engineer` (an AI agent in that role)
- **Status:** the contract three lanes build to, in separate git worktrees. No feature code is built.
- **Built from:** the four Ask specs beside this one:
  - `2026-11-19-ask-ux.md` (product designer): screens, words, states.
  - `2026-11-19-ask-ai.md` (AI efficiency lead): the call, prompt, eval, cost. Live-tested, 115 of 116.

Where this contract and a spec disagree, this contract wins. Where this contract is silent, the spec for that lane's area holds.

## 0. In one minute

- **One route,** `/api/ask`: POST asks, GET reads today's thread, DELETE clears it. `POST /api/ask/consent` accepts the one-time notice.
- **Code decides the kind.** The model's label is a hint that can only raise it. Code writes every safety line and both phone buttons.
- **5 questions a person per IST day,** outside the plan. Off-topic counts. Code-written urgent and crisis replies don't. Failures hand the question back, with at most 10 model calls a person a day. One question in flight. The server makes ids.
- **A global breaker,** `ASK_DAILY_MAX` (default 2,000 model calls a day, 0 switches Ask off), emails the founders at 80% and 100%.
- **Today only.** The next morning's daily job deletes the words and keeps counts and kinds.
- **Founders first:** only `BLOG_OWNER_EMAILS` see Ask until `ASK_OPEN=all`.
- **Three lanes:** A builds data, limits and the route; B builds the AI; C builds the UI. Section 15 says who owns each file; section 16 gives the exact seams.

## 1. What was settled

Mayank's calls and the orchestrator's defaults, applied throughout:

- **Scope:** food and diet, exercise and gym, general health, and app help. Anything else gets a short redirect.
- **Model:** Haiku 5.5 as `MODELS.ask` (`CLAUDE_MODEL_ASK`), thinking off, a hand-written JSON schema (not `betaZodOutputFormat`, which drops enums), prompt caching on, the last 2 turns from today resent.
- **What the model sees:** everything on the allowlist (threats D4/D5), including the newest report's markers. No names, no web-sourced text. Free text goes in as length-capped JSON strings. Code-derived safety facts go in a system message after the user turn.
- **Safety in code:** code decides the kind and writes the notices and the `tel:` buttons (112, Tele-MANAS 14416). While an urgent result stands, Ask answers only app and meal-logging questions. Output filters per the threats spec, allowing negations. One retry when the answer's script doesn't match the question's. Notices are English for now.
- **Counting:** as in section 0.
- **Retention:** today only. A report delete blanks the answers that used reports. An account delete takes everything.
- **Access:** founders first. Signed out, not onboarded, or under 18 by birth year: no Ask.
- **Consent:** "and your questions" joins the onboarding consent line. People who consented before Ask see a one-time notice (`profiles.ask_consent_at`).
- **The newest report:** by collection date, through a reusable helper. Moving Home and Stack to it is a follow-up.
- **Language:** answers in the question's language, up to 80 words. Starters follow the read language (en, hi, hinglish).
- **The UX spec's choices:** the top-bar control, the sheet, Jump to, "Ask about this" prefill links, and its 13 link ids.

## 3. The API

### 3.1 Rules for every method

- **No caching:** every response sends `cache-control: no-store`. Nothing in the Ask path uses `"use cache"`, `unstable_cache` or `cacheLife`.
- **The route file:** `app/api/ask/route.ts` exports `GET`, `POST`, `DELETE` and `export const maxDuration = 30` (a literal; Next reads it statically). It exports no `runtime` (Cache Components forbids it) and no `preferredRegion` (deprecated; `vercel.json` pins `bom1`).
- **Origin:** POST, DELETE and the consent POST need `sameOrigin(request)` (`lib/auth/origin.ts`), else 403 `bad_origin`.
- **Ownership:** every query takes the user id from the session, never from the request.
- **Logs:** never the question, answer, pack, a marker, a medicine or a meal title. One line per question: `[ask] kind=<kind> counted=<0|1> raised=<0|1> filter=<name|-> left=<n> ms=<n>`. Errors log their class name and status only, never `error.message`.
- **The body shape on errors:** `{ error, left?, day?, resetsAt? }` (`AskError`). The day fields appear once the person is known. The browser keys on `error`, never the status.

### 3.2 `POST /api/ask`

**Request** (`AskRequest`, strict: unknown keys give 400 `invalid`):

```ts
{
  clientKey: string;        // a UUID the browser makes; the same on "Try again"
  question: string;         // 2–300 code points, ≤ 2,000 bytes, after cleaning
  about?:                   // from "Ask about this"
    | { type: "marker"; id: string }        // markers.id
    | { type: "meal"; id: string }          // food_logs.id
    | { type: "stack_item"; nutrient: string }
    | { type: "gaps" };
}
```

**Checks, in this order.** Cheap ones come first, and the safety replies come before the switches, so a crisis question is answered even when Ask is off, paused or at its limit.

| # | Check | Result |
| --- | --- | --- |
| 1 | `sameOrigin` | 403 `bad_origin` |
| 2 | `content-type` is `application/json` | 415 `bad_type` |
| 3 | Body over 4,096 bytes (`Content-Length`, then a capped read) | 413 `too_large` |
| 4 | Session (`apiUser`) | 401 `signed_out` |
| 5 | Burst: 6 a minute per person, 30 per 10 minutes per IP (`allowRequest`) | 429 `rate_limited` |
| 6 | Profile and `askGate` | `closed` or `under_18`: 403 `not_allowed`. `not_onboarded`: 409. |
| 7 | `profiles.ask_consent_at` is null | 409 `consent_needed` |
| 8 | zod parse, then `cleanQuestion` (threats D3: NFC; controls, zero-width, bidi and tag characters out; joiners kept, at most 20; no character over 8 code points; whitespace collapsed) | 400 `invalid`, `empty` or `too_long` |
| 9 | Load, in one parallel batch: today's turns, the counters, `AskData`, and `about` resolved in their own data (anything not found is ignored) | |
| 10 | An answered turn with this `clientKey` | 200 with that turn; nothing counted |
| 10b | A pending turn with this `clientKey` | 409 `busy` |
| 11 | `askPreCheck` returns a reply (crisis, emergency, or an urgent-flagged marker named) | Save a free turn (answered, `counted = false`, no claim), 200 |
| 12 | `aiMode() === "off"`, or `ASK_DAILY_MAX` is 0 | 503 `ai_off` |
| 13 | Any other pending turn under 45 s old | 409 `busy` (the claim checks again under the lock) |
| 14 | The claim (data spec §1.3) | `limit`: 200 `{ kind: "limit", turn: null }`. `too_many_tries`: 429. `busy`: 409. `paused`: 503, plus the cap alert. A repeated `clientKey`: look the turn up and answer as in 10. |
| 15 | `answerAsk(input, { signal: AbortSignal.timeout(20_000) })` | |
| 16 | `ok`: complete with `counted = countsAgainstDay(kind)` | 200 with the turn. If complete saves nothing, a report delete reached it: release, 409 `report_deleted`. |
| 16b | Not ok | Release, then 422 `refused`, 502 `failed`, 504 `timeout` or 503 `ai_off` |
| 16c | Anything thrown | Release, 500 `error` |
| 17 | `after()` | The 80% alert when this claim's everyone-count reached it |

Release always runs in `finally` unless the turn was saved, as `app/api/food/route.ts` does for meals.

Consent (7) comes before the safety replies (11) on purpose. The sheet shows the notice in place of the box, so only a hand-made request reaches step 7 without consent, and nothing is stored or sent before it.

**200** (`AskPostOk`): `{ kind, turn, left, day, resetsAt }`. `kind: "limit"` carries `turn: null` and saved nothing. Every other kind carries the saved turn.

### 3.3 `GET /api/ask`

No query. Order: session (401), 60 a minute per person (429 `rate_limited`), profile and `askGate` (403 or 409), then one parallel batch.

**200** (`AskThread`):

```ts
{
  turns: AskTurn[];            // today's answered turns, oldest first
  pending: { clientKey, question, at } | null;   // in flight, under 45 s old
  left, day, resetsAt,
  state: "ready" | "paused" | "off",
  consentNeeded: boolean,      // GET never answers 409 for this; the sheet shows the notice
  pinned: { urgent: string[], printedFor: string | null },
  report: "none" | "reading" | "ready",
  region: "in" | "other",
  readLanguage: "en" | "hi" | "hinglish",
  starters: AskStarterFacts,
}
```

**How a stored turn becomes an `AskTurn`:**
- `links`: each stored id through `askLinkHref(id, newestReportId)`; nulls dropped.
- `removed`: `"report_deleted"` when `removed_at` is set. Then `answer` is null, `links` empty, `notice` null.
- `stale`: true when the turn is older than the newest ready report's `analyzed_at`, or older than the current stack's `created_at`.
- `demo`: `model === "mock"`.

**`left`** is `attempts >= 10 ? 0 : 5 − used`.

**`region`** is `"in"` when the profile's time zone is `Asia/Kolkata` or `Asia/Calcutta`, or unset. Otherwise `"other"`.

### 3.4 `DELETE /api/ask` ("Clear now")

Origin, session, `askGate`. It deletes the person's answered turns (any day; a turn in flight stays). It returns `{ cleared, left }`, with `left` unchanged: questions already used still count.

### 3.5 `POST /api/ask/consent`

Origin, session, `askGate`. It sets `profiles.ask_consent_at = now()` if it's null, and returns `{ consentAt }`. Repeating it changes nothing.

### 3.6 Error codes

`ASK_ERROR_STATUS` in `lib/ask/types.ts` is the source. No error uses a question.

| HTTP | `error` | When |
| --- | --- | --- |
| 400 | `invalid`, `empty`, `too_long` | Bad body, under 2 characters, over 300 characters or 2,000 bytes |
| 401 | `signed_out` | No session |
| 403 | `bad_origin`, `not_allowed` | Another site's page; Ask isn't open to this account |
| 409 | `not_onboarded`, `consent_needed`, `busy`, `report_deleted` | Setup; the notice; one in flight; report deleted mid-answer (handed back) |
| 413 | `too_large` | Body over 4 KB |
| 415 | `bad_type` | Not JSON |
| 422 | `refused` | The model declined (handed back) |
| 429 | `rate_limited`, `too_many_tries` | Burst; 10 model calls today |
| 500 | `error` | Our own failure (handed back) |
| 502 | `failed` | Anthropic error, bad output, out of tokens (handed back) |
| 503 | `ai_off`, `paused` | No key or `ASK_DAILY_MAX=0`; the day's breaker tripped |
| 504 | `timeout` | The 20 s AI deadline (handed back) |

## 6. Kinds: who decides, and what counts

The order is `answer = off_topic < doctor < urgent < crisis` (`KIND_RANK`). The final kind is the highest signal. The model can raise a kind, never lower it. Every turn rebuilds the floor from the database, never from history.

### 6.1 Before the model (`askPreCheck`; no call, free, saved)

| # | Signal | Kind | Notice parts |
| --- | --- | --- | --- |
| 1 | The crisis list matches the question | `crisis` | `crisis` |
| 2 | The emergency list matches the question | `urgent` | `symptom` |
| 3 | An urgent-flagged marker is named in the question (catalogue key, name, aliases and everyday words: iron→ferritin, sugar→HbA1c and glucose, kidney→eGFR and creatinine, blood or khoon→haemoglobin) or is the `about` marker | `urgent` | `urgent_marker` |

Lists match on a folded copy: NFKC, lower case, invisible characters out, look-alike letters folded. English, Hindi and Hinglish to start. They lean towards showing help, but skip everyday words (row 27 of section 2).

### 6.2 After the model (`answerAsk`, in order)

| # | Signal | Kind | Notice parts | AI text |
| --- | --- | --- | --- | --- |
| 4 | The model says `crisis` | `crisis` | `crisis` | dropped |
| 5 | The model says `urgent` | `urgent` | `urgent_marker` if an urgent-flagged marker is touched, else `symptom` | dropped |
| 6 | An urgent-flagged marker is in the model's `markers` | `urgent` | `urgent_marker` | dropped |
| 7 | **The urgent hold (M4):** the newest report has any urgent flag, and the question isn't app-only. App-only means `topics` includes `app` and none of `supplements`, `medicine`, `pregnancy`, `symptom`, `mental_health`. | `urgent` | `urgent_hold` | dropped |
| 8 | A doctor-flagged marker is touched (question, `about`, or the model's `markers`) | `doctor` | `doctor_marker` | kept, after filters |
| 9 | `topics` includes `medicine` | `doctor` | `medicine` | kept, after filters |
| 10 | Pregnant, and `topics` includes `supplements` or `pregnancy` | `doctor` | `pregnancy` | kept, after filters |
| 11 | The model says `doctor` and no line was added yet | `doctor` | `doctor_general` | kept, after filters |
| 12 | A flagged marker is named only in the answer | unchanged | its marker line is added | kept |
| 13 | The model says `off_topic` and nothing above raised it | `off_topic` | any from row 12 | kept; links dropped |

Model keys are lower-cased before matching (it once wrote "eGFR").

### 6.3 Output filters (threats D8), after the floor

Run on the parsed answer before anything is stored. Indian digits become 0–9 and unit words become symbols, for matching only. **Every safety filter lets negated forms through:** "can't say whether you have", "I can't tell if you have", "don't double your metformin", "no doctor reviews these". The AI spec measured 4 correct refusals the plain patterns would have wiped out.

| Filter | Trips on | Result |
| --- | --- | --- |
| Contact | URLs, bare domains, emails, phone numbers of 6+ digits, `wa.me` | Stripped from the text |
| Format | Markdown, HTML tags, invisible characters | Stripped |
| Dose | A number with mg, mcg or IU that isn't in their own data (stack doses, marker values, targets) or their question. Any such number when the stack is held or stale, or they're pregnant. | Answer removed; kind at least `doctor`; `dose`; link `stack` |
| Diagnosis | "you have / you've got / you're" with a condition word; Hindi "आपको … है" and Hinglish "aapko … hai" forms | Answer removed; at least `doctor`; `doctor_general` |
| Authority | "doctor approved / cleared / reviewed / said", "doctor-reviewed", "reviewed by our", "D-Human recommends", "partner", "sponsored" | Answer removed; at least `doctor`; `doctor_general` |
| Medicine change | stop, skip, reduce, increase, double or halve with a medicine word; "दवा बंद" | Answer removed; at least `doctor`; `medicine` |
| Brand | The fixed list (Indian supplement, pharmacy, lab and food brands) plus `AskData.stackBrands` | Answer becomes "Brand picks live in your stack, under our no-partners note."; link `stack`; kind unchanged |
| Low calories | "skip meals / dinner to lose", "eat once a day to lose", "fast for N days". A daily kcal figure under a floor only once Mayank sets one (M6). | Answer removed; at least `doctor`; `low_calorie` |
| Reassurance | When the kind is `doctor` or higher: "no need to see a doctor", "nothing to worry about", "it's fine", "safe to ignore" | Answer removed; `doctor_general` added |

Then the caps: 80 words and 1,200 characters, cut at the last full sentence that fits; 2 links.

### 6.4 What counts

| Outcome | Model called | Uses a question | Adds a model call | Saved |
| --- | --- | --- | --- | --- |
| `answer`, `off_topic`, `doctor` | yes | **yes** | yes | yes |
| `urgent` or `crisis` from `askPreCheck` | no | no | no | yes, free |
| `urgent` or `crisis` after the model | yes | no (handed back on complete) | yes | yes |
| Refused, failed, timeout, report deleted mid-answer, our error | maybe | no (released) | yes | no |
| `limit`, `busy`, `paused`, `rate_limited`, `too_many_tries`, a send that never arrived | no | no | no | no |

A repeat of an answered `clientKey` returns the saved turn and counts nothing. So an answer lost on the way (the browser shows offline) counts once, as the server answered it, and every resend of it (the automatic one, Try again, or the box with the words unchanged; §16.2) counts nothing more.

## 8. Limits, the day and the breaker

- **Numbers:** `ASK_LIMITS` in `lib/ask/types.ts`. No lane types a limit by hand.
- **The day:** `istDay(now)`, always IST, from the server's clock (Lane A). The day is stored on the turn and the counter; complete and release use the stored day. `resetsAt` is the next midnight IST (18:30 UTC). IST has no daylight saving.
- **The ledger:** the data spec's §1.3 claim (four statements, one transaction, the person's row locked first), §1.4 complete and release, and Appendix A.2's SQL. Lane A may write them with drizzle's `onConflictDoUpdate({ setWhere })` or as `sql` templates.
- **Free turns** (`askPreCheck` replies) skip the claim. Lane A inserts them answered with `counted = false`, and adds 1 to `ask_totals.crisis` or `.urgent` (not `attempts`).

- **Alerts:** `sendFounderAlert` from `after()`. One at the claim that reaches `ceil(0.8 × max)`, one at the first refusal. Marked once a day in `job_runs` as `alert:ask-80:<day>` and `alert:ask-cap:<day>`, as `capAlert` does. ## 11. The daily purge

- **Where:** `housekeeping()` in `lib/email/jobs.ts` adds `purgeAsks(d, now)` (Lane A, `lib/platform/ask.ts`) to its `Promise.all`. Its counts go in `housekeeping.askTurns` and `housekeeping.askDays`.

## 16. Seams

### 16.1 Lane A calls Lane B: exactly two functions, in `lib/ai/ask.ts`

```ts
export function askPreCheck(input: { question: string; about: AskAboutResolved | null; data: AskData }): AskReply | null;
export async function answerAsk(input: AskInput, opts: { signal: AbortSignal }): Promise<AskAnswer>;
```

- `askPreCheck` is pure and synchronous: section 6.1. Null means "ask the model".
- `answerAsk` does section 6.2 onwards: pack, call (live or mock by `aiMode()`), lenient parse, the language retry, the floor, the filters and the caps. It honours `signal` and returns `{ ok: false, error: "timeout" }` when it fires. It never throws for refusals, bad output or Anthropic errors. Anything it does throw is Lane A's 500.
- `AskData` is built by Lane A, already on the allowlist. Lane B never queries the database.
- `AskReply.links` are ids. Lane A stores ids and makes hrefs when it reads a turn back.
- `AskUsage.costMicros` is `round(costOf(message) × 1e6)`; `inputTokens` counts cached and uncached input together.

Lane A's tests stub `@/lib/ai/ask` with `allowAppImports` (`tests/support/app.ts`), so they never depend on Lane B's code or the mock's keywords.

### 16.2 Lane C calls Lane A over HTTP only

Through `send()` in `components/platform/net.ts`, with the types in `lib/ask/types.ts`.

- **POST** with `timeoutMs: ASK_LIMITS.clientTimeoutMs` and `wholeAnswer: true`. `send` reports a timeout, and an answer cut off on the way, as `offline`. If 24 s or more passed, treat it as a timeout: GET, find the turn by `clientKey`, and while it's `pending`, ask GET again every 2 s, up to 45 s after the send.
- **One automatic resend (2026-11-22, Mayank's approval).** A quick `offline` (under 24 s) is resent once, after `RESEND_AFTER_MS` (1 s), with the same body and so the same `clientKey`. iPhone's WebKit never resends a POST that died on a connection the network dropped while the sheet sat open (the Jio pattern at bom1; lane B's report). Never resent after an HTTP status, or after the 25 s wait. The server makes it safe: an answered `clientKey` is replayed and counts nothing (step 10, from any day, so a resend across midnight IST counts nothing today); a pending one is 409 `busy` (10b); consent (7) is checked first, so a resend never gets past a missing notice.
  - After the resend, `busy` (the first send still being answered) and a 500 `error` (which can't say whether the first send was answered) go to the GET lookup above instead of the sheet: the answer if it landed, else that error, now known not to have counted.
  - Two quick drops are `offline`. So is a lookup in which no GET got through: nothing is known, so the sheet doesn't say "It didn't count". The offline words say what holds either way: "It won't count twice."
- **"Try again"** resends the same `clientKey`, and so does the box's own Ask with the words unchanged. A new question gets a new `crypto.randomUUID()`.
- **GET** again when the sheet opens and when the page becomes visible: Next keeps hidden screens mounted (threats D14).
- **A new `day`** in any reply drops the old turns from view.
